# Mode : offre -- Evaluation complete A-F

Quand le candidat colle une offre (texte ou URL), TOUJOURS livrer les 6 blocs.

Principes obligatoires :
- Ne jamais inventer d’expérience, de diplôme, de certification ou de responsabilité.
- Si une information n’est pas présente dans `cv.md` ou `config/profile.yml`, écrire clairement qu’elle n’est pas documentée.
- Adapter l’analyse au marché suisse et francophone par défaut.
- Utiliser un ton sobre, professionnel, direct, sans flatterie excessive.
- Distinguer clairement les domaines du candidat : restauration, IT/web, hébergement, photographie, communication et support client.
- Ne pas mélanger inutilement les expériences restauration et IT : n’utiliser les expériences transversales que lorsqu’elles renforcent l’offre.

## Etape 0 -- Detection d'archetype

Classer l'offre dans l'un des archetypes suivants. Si l’offre est hybride, indiquer les 2 plus proches.

Archetypes principaux :
- Restauration / Cuisine
- Gestion de restaurant / Direction opérationnelle
- Production alimentaire / Collectivité / Médico-social
- Support IT / Helpdesk / Service Desk
- Administration web / Webmaster / CMS
- Hébergement / DNS / Email / Infrastructure légère
- Support Apple / Environnement Mac
- Photographie / Création de contenu visuel
- Communication digitale / Community management
- Poste hybride opérationnel + digital

Cela determine :
- Quels proof points prioriser dans le bloc B
- Comment reecrire le summary dans le bloc E
- Quelles stories STAR preparer dans le bloc F
- Quelles expériences minimiser pour éviter une candidature dispersée

## Bloc A -- Resume du role

Tableau avec :
- Archetype detecte
- Domaine : Restauration / IT-web / Hébergement / Photo / Communication / Support client / Hybride
- Fonction : Production / Support / Administration / Gestion / Conseil / Création de contenu / Coordination
- Seniorite
- Remote : Full remote / Hybride / Sur site / Déplacements
- Taille d'equipe si mentionnee
- Type d’environnement : PME / collectivité / agence / institution / association / hôtellerie-restauration / entreprise IT
- TL;DR en 1 phrase

## Bloc B -- Match avec le CV

Lire `cv.md` et `config/profile.yml`. Creer un tableau ou chaque prerequis de l'offre est mappe sur des lignes ou expériences exactes du CV.

Le tableau doit contenir :
| Prérequis de l’offre | Preuve dans le CV | Niveau de match | Commentaire |
|---|---|---|---|

**Adapte a l'archetype :**

- Restauration / Cuisine ->
  prioriser CAP cuisine, expérience longue en cuisine, HACCP, production, brigade, menus, service, gestion des volumes, postes de chef/sous-chef/cuisinier.

- Gestion de restaurant / Direction opérationnelle ->
  prioriser direction, gestion d’équipe, fournisseurs, coûts, rentabilité, recrutement, organisation, chiffre d’affaires, expérience client.

- Production alimentaire / Collectivité / Médico-social ->
  prioriser production, hygiène, sécurité alimentaire, travail en équipe, adaptation à des publics spécifiques, expérience en collectivité, médico-social ou réinsertion.

- Support IT / Helpdesk / Service Desk ->
  prioriser support client, diagnostic, environnement Apple, expérience Fnac/Swisscom, résolution de problèmes, pédagogie, contact utilisateur, autonomie.

- Administration web / Webmaster / CMS ->
  prioriser WordPress, administration de sites, gestion de contenus, maintenance, formulaires, thèmes, plugins, responsive, SEO de base, expérience associative.

- Hébergement / DNS / Email / Infrastructure légère ->
  prioriser Infomaniak, domaines, DNS, redirections, SSL, emails, configuration SMTP, hébergement mutualisé, dépannage technique.

- Support Apple / Environnement Mac ->
  prioriser certifications Apple, expérience Apple Product Professional / Apple Sales Professional, support Mac/iPhone, environnement Apple, conseil client.

- Photographie / Création de contenu visuel ->
  prioriser portfolio, photographie aviation militaire, événements, sélection/tri, post-traitement, publication web, communication visuelle.

- Communication digitale / Community management ->
  prioriser gestion de sites, réseaux sociaux, communication associative, publication d’articles, gestion d’image, contenus web.

- Poste hybride opérationnel + digital ->
  valoriser la double compétence terrain + numérique, la capacité à comprendre les besoins opérationnels et à les traduire en solutions web/IT simples.

Section **Lacunes (Gaps)** avec strategie de mitigation pour chacune. Pour chaque lacune :
1. Est-ce un bloqueur dur ou un nice-to-have ?
2. Le candidat peut-il demontrer une experience adjacente ?
3. Y a-t-il un projet portfolio qui couvre cette lacune ?
4. Plan de mitigation concret : phrase pour la lettre de motivation, formation courte, mini-projet, preuve à ajouter au portfolio.

Ne jamais transformer une expérience adjacente en compétence directe. Formuler avec prudence :
- “expérience transférable”
- “compétence adjacente”
- “base opérationnelle solide”
- “à consolider par une formation courte”

## Bloc C -- Niveau et strategie

1. **Niveau detecte** dans l'offre vs **niveau naturel du candidat pour cet archetype**
2. **Plan "vendre senior sans mentir"** :
   - formulations spécifiques adaptées à l’archetype
   - réalisations concrètes à mettre en avant
   - comment valoriser l’expérience opérationnelle, la polyvalence, l’autonomie et le contact client
   - pour l’IT/web : vendre l’expérience terrain, la résolution de problèmes et l’administration réelle de sites, sans prétendre être développeur senior
   - pour la photo : vendre la pratique, le portfolio, la rigueur et l’œil visuel, sans inventer de diplôme photo
   - pour la restauration : vendre l’expérience longue, la gestion et la fiabilité
3. **Plan "si je suis downlevel"** :
   - accepter si la rémunération est juste
   - négocier une revue à 6 mois
   - demander des critères clairs de progression
   - positionner le poste comme une entrée solide dans le domaine ciblé si nécessaire

## Bloc D -- Remuneration et demande

Utiliser WebSearch pour :
- Salaires actuels du role en Suisse ou en Suisse romande en priorité
- Salaires actuels du role en France uniquement si l’offre est française
- Données issues de sources vérifiables : Glassdoor, jobs.ch, Indeed Salaires, Talent.com, Salarium/OFS si pertinent, conventions collectives si applicables, sites employeurs
- Reputation de remuneration de l'entreprise si disponible
- Tendance de demande du role sur le marche suisse/francophone

Tableau avec donnees et sources citees. Si pas de donnees, le dire clairement -- ne rien inventer.

**Marché suisse -- Verifications obligatoires :**
- Salaire annuel ou mensuel ?
- 13e salaire mentionné ?
- Taux d’activité : 80%, 90%, 100% ?
- Heures hebdomadaires ?
- Lieu de travail et coûts de déplacement ?
- Télétravail ou présence obligatoire ?
- CCT applicable si restauration, hôtellerie, collectivité ou domaine parapublic ?
- Permis requis ou statut de travail : préciser que le candidat est titulaire d’un permis C suisse.
- Langues demandées : français, allemand, anglais.
- Si poste temporaire : durée, possibilité de fixe, agence impliquée.

**Marché français -- Verifications obligatoires si l’offre est en France :**
- 13e mois / prime de fin d'annee mentionne ? L'inclure dans le calcul brut annuel.
- Part variable ?
- Interessement / Participation mentionnes ?
- Convention collective applicable ?
- CDI ou CDD ?
- Freelance / Portage salarial ?

## Bloc E -- Plan de personnalisation

| # | Section | Etat actuel | Changement propose | Justification |
|---|---------|-------------|--------------------|---------------|
| 1 | Summary | ... | ... | ... |

Top 5 modifications du CV + Top 5 modifications LinkedIn pour maximiser le match.

Règles :
- Si l’offre est IT/web, réduire fortement la restauration et la présenter uniquement comme preuve de relation client, gestion, rigueur et autonomie.
- Si l’offre est restauration, réduire fortement l’IT et la photo.
- Si l’offre est photo/communication, valoriser le portfolio, la publication web et les projets associatifs.
- Si l’offre est support IT, mettre en avant Apple, Fnac, Swisscom, pédagogie, diagnostic et contact client.
- Si l’offre est hébergement/web, mettre en avant DNS, domaines, emails, WordPress, Infomaniak, SSL, SMTP, maintenance.

Inclure une proposition de **résumé CV personnalisé** de 3 à 5 lignes.

Inclure une proposition de **lettre de motivation courte** en 3 paragraphes :
1. Pourquoi cette entreprise / ce poste
2. Correspondance entre les besoins de l’offre et le parcours du candidat
3. Conclusion avec disponibilité pour un entretien

La lettre doit être :
- sobre
- professionnelle
- francophone/suisse
- sans flatterie excessive
- sans invention
- adaptée au domaine détecté

## Bloc F -- Plan d'entretiens

6-10 stories STAR+R mappees sur les prerequis de l'offre :

| # | Prerequis de l'offre | Story STAR+R | S | T | A | R | Reflection |
|---|---------------------|--------------|---|---|---|---|------------|

La colonne **Reflection** capture ce qui a ete appris ou ce qui serait fait differemment.

**Story Bank :** Si `interview-prep/story-bank.md` existe, verifier si ces stories y sont deja. Sinon, ajouter les nouvelles. Avec le temps, cela construit une banque reutilisable de 5-10 stories maitre adaptables a n'importe quelle question d'entretien.

**Selectionnees et cadrees selon l'archetype :**
- Restauration / Cuisine -> mettre en avant production, service, pression, hygiène, équipe, adaptation
- Gestion de restaurant -> mettre en avant rentabilité, fournisseurs, recrutement, gestion d’équipe, relation client
- Production alimentaire / Médico-social -> mettre en avant rigueur, hygiène, adaptation au public, fiabilité
- Support IT -> mettre en avant diagnostic, pédagogie, gestion client, résolution rapide
- Administration web / Webmaster -> mettre en avant sites gérés, corrections, maintenance, WordPress, contenus
- Hébergement / DNS / Email -> mettre en avant résolution technique, configuration, tests, documentation
- Support Apple -> mettre en avant conseil, diagnostic, écosystème Apple, certifications
- Photographie -> mettre en avant préparation, prise de vue, tri, post-traitement, livraison
- Communication digitale -> mettre en avant publication, cohérence éditoriale, réseaux sociaux, contenu web
- Hybride -> mettre en avant capacité à relier terrain, utilisateurs et outils numériques

Inclure aussi :
- 1 case study recommandee : projet à présenter et angle conseillé
- Questions red-flag et comment y repondre, par exemple :
  - “Pourquoi avez-vous plusieurs domaines professionnels ?”
  - “Pourquoi revenir vers l’IT après la restauration ?”
  - “Êtes-vous développeur ou plutôt administrateur web/support ?”
  - “Pourquoi un changement après si peu de temps ?”
  - “Votre expérience photo est-elle professionnelle ?”
  - “Pourquoi ce poste plutôt qu’un poste de chef de cuisine ?”

## Post-evaluation

**TOUJOURS** executer apres les blocs A-F :

### 1. Sauvegarder le report .md

Sauvegarder l'evaluation complete dans `reports/{###}-{company-slug}-{YYYY-MM-DD}.md`.

- `{###}` = prochain numero sequentiel, 3 chiffres, zero-padded
- `{company-slug}` = nom d'entreprise en minuscules, sans espaces, utiliser des tirets
- `{YYYY-MM-DD}` = date du jour

**Format du report :**

```markdown
# Evaluation : {Entreprise} -- {Role}

**Date :** {YYYY-MM-DD}
**Archetype :** {detecte}
**Score :** {X/5}
**URL :** {URL de l'offre}
**PDF :** {chemin ou en attente}

---

## A) Resume du role
(contenu complet du bloc A)

## B) Match avec le CV
(contenu complet du bloc B)

## C) Niveau et strategie
(contenu complet du bloc C)

## D) Remuneration et demande
(contenu complet du bloc D)

## E) Plan de personnalisation
(contenu complet du bloc E)

## F) Plan d'entretiens
(contenu complet du bloc F)

## G) Brouillons de reponses pour la candidature
(uniquement si score >= 4.5 -- brouillons de reponses pour le formulaire de candidature)

---

## Mots-cles extraits
(liste de 15-20 mots-cles de l'offre pour l'optimisation ATS)
```

### 2. Enregistrer dans le tracker

**TOUJOURS** enregistrer dans `data/applications.md` :
- Prochain numero sequentiel
- Date du jour
- Entreprise
- Role
- Score : moyenne du match, de 1 à 5
- Statut : `Evaluated`
- PDF : non, ou oui si l'auto-pipeline a genere un PDF
- Report : lien relatif vers le fichier report, exemple `[001](reports/001-company-2026-01-01.md)`

**Format du tracker :**

```markdown
| # | Date | Entreprise | Role | Score | Statut | PDF | Report |
```
